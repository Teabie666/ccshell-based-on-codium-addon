# 0004 一个进程管多个窗口，一个文件夹一个窗口

- 状态：已采纳（2026-10-10）

## 背景

M3 之前一个进程只有一个窗口、一个工作区（文件夹）。M4 要做的几件事都要求同时开多个文件夹：插件的"在新窗口中打开文件夹"、标题栏「文件夹 ▾」、第二次启动时把参数转给已经在运行的实例（单实例），以后还有每个窗口各用一个 API 接口。

## 决定

一个主进程管所有窗口，跟 VS Code 一样：

- **全局的一份**（`host/main/shellApp.ts`）：设置、插件的 globalState、主题、界面语言、webview 文档、`ccw:` 协议、单实例，以后还有 API 接口和插件管理。
- **每个窗口一份**（`host/main/windowContext.ts`）：窗口本身、它的工作区和 workspaceState、它的插件进程（extension host）。
- **一个文件夹最多一个窗口**：再打开同一个文件夹就切到那个窗口。在当前窗口打开别的文件夹 = 替换这个窗口的工作区（照 VS Code 重新加载窗口的做法：先停插件进程，插件把打开的对话记在旧文件夹名下，再按新文件夹重新加载页面）。
- **单实例按数据目录**：`app.requestSingleInstanceLock` 的锁在 userData 里，所以同一个数据目录只有一个实例，`--user-data-dir` 不同的实例（比如测试）互不干扰。

## 考虑过的其他做法

- **每个文件夹一个进程**：单实例锁按数据目录算，几个进程会抢同一把锁，"把参数转给谁"说不清；设置、globalState 这些文件会被几个进程同时写、互相覆盖。
- **只有一个窗口**：打开别的文件夹就替换当前的。最省事，但两个项目没法并排开，也没法让两个窗口各用一个接口。

## 后果

- 渲染进程的 IPC 按发送的窗口分发；设置、主题、语言变了要通知所有窗口。
- 插件的 globalState 由所有窗口的插件进程共用：一个窗口写了，主进程转给其他窗口的插件进程（`storage.didChange`），VS Code 也是这样同步的。workspaceState 只属于一个窗口（一个文件夹一个窗口）。
- 每个窗口一个插件进程，各自起 claude 进程、各自写 `~/.claude/ide/` 下的锁文件，跟 VS Code 多窗口一样。
- 同源页面的缩放在 Chromium 里本来就是一起变的，所以缩放级别也是全局一份。
- 窗口的位置按文件夹记，另外记最近打开的文件夹和退出时开着的窗口（`state/shell.json`，不放进插件的 globalState）。
